## 本次调整

| 修改 | 原有行为 | 现在的行为 | 重点走查 |
|---|---|---|---|
| 保存后继续其他活动 | 查看进度后开始新运动会返回旧保存页 | 可以进入新活动；上一条记录保留且只计一次 | 保存学习休息 → View Progress → 运动计划 → Start Activity |
| 实际活动日期 | 可填写未来日期并提前获得进度 | 只能保存今天或以前的实际记录 | Add Manual Record填明天，应出现日期提示 |
| 备用方案返回 | 顶部返回丢输入，底部返回保留 | 两种返回都保留备用输入 | 修改备用活动 → 顶部Back → Next，再重复底部Back |
| 每周目标 | 再次安排未来目标可能使当前目标回退 | 已生效目标保留，下一周使用新目标 | 目标90生效后预约120，本周仍为90 |
| 运动改期 | 可以改到过去并继续显示待完成 | 过去日期和当天过去时间均有错误提示 | Reschedule选择过去日期或今天00:00 |
| 宠物进度文案 | 本阶段已积累值被标为距升级所需 | 分别显示已积累和剩余值 | 总分38时，本阶段8/30、距下级22 |
| 实际运动强度（用户已批准） | 名称关键词猜测，需Edit才能改 | 确认页直接必选Actual intensity，补录运动也需选择 | 不选强度时保存被阻止；选择后可保存 |
| 准备入口文案（用户已批准） | 多个入口均使用Start，易误以为已开始计时 | 首页Open Study Session、提醒Prepare Break、计划Prepare Activity | 准备页仍由Start Activity手动开始计时 |
| 保存反馈（用户已批准） | 首先突出点数，宠物关闭时仍可能显示等级 | 先展示名称、时长、类别；轻量运动解释统计，关闭宠物隐藏等级 | 分别保存Light和Moderate，核对反馈及周分钟 |

界面继续使用原有灰度布局。版本标识更新为V2；现有三个组件、两类活动、积分规则和宠物开关原则保持一致。

## 实现与边界

- 活动记录和目标辅助逻辑：`src/model.js`。
- 页面、草稿、保存退出、目标与改期：`src/App.jsx`。
- 自定义业务校验继续使用共享英文字段错误：`src/Form.jsx`、`src/validation.js`。
- 已保存活动从反馈页离开时，休息后的学习会暂停；需回学习页明确继续，避免离开反馈后暗中计时。
- 旧的未来记录不会被删除，仍可在历史中更正；在其日期未到之前不计入当前进度。没有增加完整数据迁移。
- 周目标仍只有当前值与一个未来预约，不提供历史目标查询；演示日期的倒退不相当于撤销目标编辑。
- 草稿刷新恢复、真实后台计时、完整存储容错、实际手机及全面无障碍仍未完成。
